# EC2
EC2(Elastic Compute Cloud)とは、必要な時に仮想サーバー（コンピュータ）をクラウド上で作成し、自由に起動・停止・スケールできるサービスです。物理サーバーを自前で用意する必要がなく、数分でサーバー環境を用意できるため、Webアプリケーションやバックエンド処理、検証環境など幅広い用途で利用されます。

### インスタンスタイプ
　EC2では、用途に応じてCPU・メモリ・ネットワーク性能などが異なる「サーバーの種類」を選ぶ必要があり、これをインスタンスタイプと呼びます。
##### 命名規則
例：`t3.micro`,`m6g.large`は分解すると次のようになります。
```code
[ファミリー][世代][オプション].[サイズ]
```
1. ファミリー
　最初のアルファベットは、そのインスタンスがどの用途に最適化されているかを示しています。
- t系：低コスト、バースト型（軽い処理向け）
- m系：バランス型（万能）
- c系：CPU特化（計算処理向け）
- r系：メモリ特化（大量データ向け）
- g系：GPU搭載（AI、画像処理向け）
2. 世代
ファミリーの後ろに続く数字は、そのインスタンスのバージョンを表し、数字が大きいほど新しく、性能やコスト効率が良いことを表します。

3. オプション
世代の後ろにつくアルファベットは、CPUの種類や追加機能を表します。
- g:Graviton（ARMベースで低コスト）
- a:AMD CPU
- n:ネットワーク性能強化
これにより、同じファミリーでも異なる特性を持つインスタンスが存在します。

4. サイズ
ドット(.)の後ろはインスタンスのサイズ（性能の大きさ）を示します。
- micro ：　最小構成
- small/medium　：　中規模
- large以上　：　高性能
サイズが大きくなるほどCPUコア数やメモリが増加し、処理能力も向上します。

##### 主要ファミリーの特徴
###### T系
T系は低コストで軽い処理に適したバースト型インスタンスです。通常は低いCPU性能で動作し、必要な時だけ一時的に性能を引き上げる仕組みになっています。
主な用途：
- 小規模なWebサービス
- 開発環境
- 軽量なAPIサーバー
コストパフォーマンスが非常に高く、最初の選択肢としてよく使われます。

###### M系
M系はCPU・メモリ・ネットワークのバランスが取れた万能型インスタンスです。特定のリソースに偏らず、安定した性能を発揮します。
主な用途：
- Webアプリケーションサーバー
- バックエンド処理
- 一般的な業務システム
「どれを選べばいいかわからない場合はM系」が基本です。

###### C系
C系はCPU性能に特化したインスタンスで、計算処理が多いワークロードに適しています。
主な用途：
- バッチ処理
- データ処理
- 高負荷API
CPU性能を最大限活かしたい場合に選びます。

###### R系
R系はメモリ容量に特化したインスタンスで、大量のデータを扱う処理に向いています。
主な用途：
- データベース
- キャッシュサーバー
- 分析処理
メモリ不足がボトルネックになる場合に最適です。

###### G系
G系はGPUを搭載したインスタンスで、並列計算が必要な処理に強みを持ちます。
主な用途：
- 機械学習
- 画像、動画処理
- AI推論
高度な計算処理が必要な場合に利用されます。

### 購入オプション
EC2では、インスタンスタイプだけでなく、どのような料金体系で利用するかも選択する必要があります。
<br>

##### オンデマンドインスタンス
　オンデマンドインスタンスは、最もシンプルで基本となる料金体系です。使った分だけ課金される従量課金モデルで、初期費用や契約は一切不要です。

インスタンスタイプの変更やスケールも自由で、短期間の利用や試験的な環境構築に最適です。一方で、割引が一切適用されないため、長期間利用する場合はコストが高くなります。

開発環境や検証環境、初期フェーズのサービスに適しています。
<br>

##### Saving Plans
Saving Plansは、一定の利用を約束することで、割引を受ける仕組みです。契約期間は1年または3年で、長いほど割引率が高くなります。最大で70％以上のコスト削減が可能です。

このモデルの大きな特徴は、柔軟性が高いことです。インスタンスタイプやリージョンを変更しても割引が適用されるため、システム構成が変わっても無駄になりにくい設計になっています。

実務では、長期運用される本番環境に対して最もよく使われる選択肢です。
<br>

##### リザーブドインスタンス
　リザーブドインスタンスは、特定のインスタンスを長期間予約することで割引を受ける方式です。Saving Plansと似ていますが、より強い制約があります。

例えば、インスタンスタイプやリージョン、AZまで固定されるため、設計変更に弱いというデメリットがあります。その代わり、安定した割引を受けることができます。

以前は主流の割引手段でしたが、Saving Plansの登場により、新規採用は減少傾向にあります。
<br>

##### スポットインスタンス
　スポットインスタンスは、AWSの過剰リソースを非常に安価に利用できる仕組みです。通常価格の最大90％割引で利用できるため、コスト削減効果は非常に大きいです。

しかし、この安さには大きな制約があります。それは**いつでも停止される可能性があること**です。AWS側のリソース需要が高まると、2分前の通知でインスタンスが終了されます。

そのため、停止されても問題ないバッチ処理やデータ分析、再実行可能なジョブなどに利用されます。
<br>

##### Dedicated Host
 Dedicated Hostは、物理サーバーを丸ごと専有する特殊なオプションです。他のユーザーとハードウェアを共有しないため、特定のコンプライアンス要件やライセンス制約に対応できます。

 ソフトウェアライセンスが「物理サーバー単位」で課金される場合や、金融や医療などの厳しい規制がある環境で利用されます。

### AMI
AMI(Amazon Machine Image)とは、EC2インスタンスを起動するための設計図です。OSやミドルウェア、アプリケーション、設定情報などがあらかじめ含まれており、AMIを指定することで同じ構成のサーバーを何度でも実現できます。

一度構築した環境をAMIとして保存しておけば、数分で同一環境を量産できるため、スケーリングや障害復旧の基盤になります。

AMIには、**再現性**、**スケーラビリティ**、**可用性**、**イミュータブル**という４つの重要な特徴があります。
イミュータブルとは、サーバーを変更せず、作り直すことで、既存サーバーを手で修正するのではなく、AMIを更新して再デプロイするというクラウド設計の基本思想を表しています。

AMIには大きく分けて３種類あります。
#### AWS提供AMI
AWSが公式に提供しているAMIで、最も基本となるものです。
- Amazon Linux
- Ubuntu
- Windows Server

#### カスタムAMI
自分で構築したEC2インスタンスから作成するAMIです。
同じ環境を何台も作る時に使います。

#### Marketplace AMI
AWS Marketplaceで提供される有料または無料のAMIです。
- WordPress環境
- セキュリティソフト
- 商用アプリケーション

### ストレージ
EC2では、サーバーのディスクとして使うストレージを選択できます。大きく分けてEBS（外付けディスク）とInstance Store（内蔵ディスク）の２種類があります。

この違いは、データの永続性に直結するため非常に重要です。
- EBS : 永続ストレージ（止めても残る）
- Instance Store : 一時ストレージ（止めたら消える）

#### Instance Store
Instance Storeとは、EC2に物理的に接続されたローカルディスクで、高速・無料というメリットがある一方、インスタンス停止・終了でデータが消失するという特徴があります。PCのRAMに近い感覚で利用するイメージです。
キャッシュ、一時ファイルなどの用途に使用します。

#### EBS
EBS(Elastic Block Store)は、EC2にアタッチする「ネットワーク越しのHDD/SDD」です。
永続的て、バックアップ（スナップショット）が可能であるという特徴を持ちます。
OS、データベース、アプリデータなどの用途に用います。

EBSには大きく次の4つのボリュームタイプがあります。

##### gp3(General Purpose SSD)
標準で最もよく使うストレージです。コストパフォーマンスが良く、IOPSやスループットを個別に調整可能です。
Webサーバー、一般アプリ、小中規模DBに用いられます。

##### io2(Provisioned IOPS SSD)
高IOPS、低レイテンシ、高耐久性という特徴を持ち、高性能です。
大規模データベースや金融システムに用いられます。
性能重視ならこれを選択します。

##### st1(Throughput Optimized HDD)
スループット重視のHDDです。大容量向けで、連続読み書きに強いという特徴を持ちます。
ログ、データ分析、バッチ処理用いられます。

##### sc1(Cold HDD)
最も安いストレージです。低性能で、低頻度アクセスのストレージに用いられます。
アーカイブやバックアップに用いられます。
